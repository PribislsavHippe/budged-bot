# Релиз 27 сентября 2026

Содержимое: ввод продаж в чате, правки в миниаппе, план продаж, чистые/грязные
чаевые и сравнение периодов, очередь повторной отправки в Google Календарь.
Прежний анимированный градиент восстановлен.

## Порядок публикации

1. Проверить в рабочем Supabase наличие таблиц `sales_months`, `sales_events`,
   `sales_reports` и колонок из v8. На старую базу выполнить `migration_v7.sql`,
   затем `migration_v8.sql`. **Не запускать заново `schema.sql` или v2–v6.**
   v7 не предназначена для повторного выполнения; обе новые миграции
   транзакционные и не удаляют существующие записи.
2. Убедиться, что `SUPABASE_KEY` на Render — серверный `service_role`,
   а `SUPABASE_URL` указывает на проверенный проект. Проверить наличие
   `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`.
   Значения ключей не переносить в документацию, коммиты или чат.
3. Отправить релизный коммит в связанную с Render ветку и дождаться статуса
   Live. Проверить, что Render показывает именно SHA релизного коммита.
4. Проверить ответ `/`, загрузку `/app` и четырёх JS/CSS-файлов,
   отказ API без Telegram-подписи, логи запуска и регистрацию webhook.
5. Открыть миниапп из Telegram и проверить чаевые, сравнение, план, историю.
   Команда `/calendar` повторяет доставку смен. Если Google отозвал refresh
   token, требуется повторное подключение самого пользователя.

Запрос для проверки структуры без чтения пользовательских данных:

```sql
select table_name, column_name, data_type
from information_schema.columns
where table_schema = 'public'
  and (table_name in ('sales_months', 'sales_events', 'sales_reports')
       or (table_name = 'users' and column_name = 'google_reconnect_required')
       or (table_name = 'shifts' and column_name in ('google_synced', 'google_sync_error')))
order by table_name, ordinal_position;
```
