# Бессрочные приглашения в ресторан

Решение согласовано владельцем 20 октября 2026 года.

## Проблема и решение

Коллега получает ссылку, но открывает её позже семи дней и не может подключиться.
Сейчас владельцу приходится создавать и пересылать новое приглашение.
Известное свидетельство — сообщение владельца о просроченных ссылках.
Гипотеза: отмена срока позволит открыть уже отправленное приглашение без повторной
переписки. Выбраны бессрочные ссылки вместо продления ещё на неделю или новой
рассылки. Ссылка создаёт заявку; право доступа к отчёту подтверждает владелец.

Сценарий: старая ссылка → ввод имени → личный бот доступен → связь с рестораном
ожидает отдельного подтверждения владельцем. Это поведение не меняется.

## Обновление

Владелец выполняет `migration_v29.sql` в SQL Editor Supabase после v28, затем
развёртывает код на Render. Миграция атомарна, повторный запуск допустим.
Новых таблиц, расширения клиентских прав и рассылки нет.

- Сохранённые в `restaurants.invite_hash` ссылки работают независимо от прежней
  даты окончания; хеши и адреса не меняются. Коллегам не нужно пересылать их заново.
- Новые приглашения не имеют срока действия.
- Создание нового приглашения по-прежнему заменяет предыдущее. Это позволяет
  владельцу отключить распространившуюся ссылку.
- Старый код, перезаписанный при создании нового приглашения, миграция восстановить
  не может. Неверные коды и приглашения ресторанов без владельца не принимаются.
- Сообщение с новой ссылкой в чате администратора теперь указывает бессрочность.
  Новых сообщений сотрудникам нет.

## Проверка

`tests/invite_sql_checks.mjs` прогоняет всю цепочку schema + v7–v29 на временной
базе: восстановление истёкшего кода, pending до подтверждения, отсутствие
автоподтверждения, чужой владелец, выбор ресторана, смена кода, неизвестный код,
роли anon/authenticated/service_role, удаление владельца, повторная миграция.
Проверка автоматически включается в общий `tests/run_checks.py`.

На рабочей базе после миграции открыть сохранившуюся старую ссылку с аккаунта
коллеги и убедиться, что после имени личный бот доступен, а связь с отчётом требует
подтверждения. Технические тесты не подтверждают эту проверку на реальных людях.
