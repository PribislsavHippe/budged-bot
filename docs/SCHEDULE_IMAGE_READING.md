# Вариативный разбор графика — 13 октября 2026

Проблема: таблица и изображение меняются; привязка к координатам одного
скриншота блокирует импорт. Свидетельство: присланный график отвергнут до
чтения имён из-за ширины первых двух столбцов.

Пользователь: сотрудник, получивший график в виде изображения.
Сценарий: прислать график и согласиться на обработку → выбрать имя → указать
месяц → проверить список смен → сохранить. Интерфейс и порядок не меняются.

Гипотеза: чтение всей таблицы при неизвестной сетке позволит разбирать разные
размеры, расположение, число сотрудников и дней без настройки шаблона.
Решение согласовано в чате: сохранить точные увеличенные фрагменты знакомой
сетки; для остальных изображений читать всю таблицу, затем только выбранного
сотрудника по имени. Поворот из EXIF учитывается; текст изображения — данные,
не инструкции. Не угадывать непонятные даты и часы.

Альтернативы: ограничить импорт одним шаблоном (не решает проблему), полностью
заменить увеличенные фрагменты чтением целого изображения (теряется детализация
мелких ячеек), подключить отдельный OCR (новая зависимость и настройка).

План: подготовка изображения → два режима чтения → проверки ответов и выбранного
имени → сохранение режима между шагами → тесты ошибок/повторов/подтверждения.
Сохранять только после существующей проверки пользователем. Изображения и
сырые ответы не записывать в журналы или базу. Ограничения размера сохраняются.

Проверка: искусственные таблицы разной формы, местоположения и ориентации;
переход от имени к сменам, отказ при неоднозначности/дубликатах, повтор после
ошибки. Отдельно нужен реальный прогон разных графиков через распознавание.
Поддержка нового размера не означает гарантии чтения размытого текста.

Проверена [документация Groq Vision](https://console.groq.com/docs/vision):
используемая модель поддерживает изображения и JSON. Новый провайдер не нужен.

## Результат проверки

- Реализованы два режима в `schedule_reader.py`. Выбранное имя проверяется
  повторно, неоднозначные ответы и повторяющиеся даты отклоняются.
- Для общего режима изображение остаётся только в оперативной памяти до
  сохранения/отмены/истечения существующего срока черновика: при смене месяца
  таблица читается снова. В знакомой сетке сохраняется прежний путь фрагментов.
- Прошли 29 проверок сценариев и шесть проверок подготовки изображения:
  новый и прежний формат, разные размеры/поля/ориентация EXIF, неверный
  сотрудник, неоднозначность, дубликаты, повтор, другой месяц и подтверждение.
- Через настоящий Groq проверены две искусственные таблицы: сотрудники в
  строках и сотрудники в столбцах. Оба раза имена и две рабочие смены выбранного
  сотрудника прочитаны верно. На первом запуске второй таблицы был лимит
  запросов; повтор после паузы прошёл. Реальные данные коллег не отправлялись.
- Это не подтверждение чтения любого изображения: ещё нужны проверки реальных
  графиков, включая мелкие и сложные таблицы. Production не проверен.
- Подготовлено к отправке в GitHub по просьбе владельца. Развёртывание на
  Render не подтверждено. Миграции не нужны.
