# Budget Bot — трекер чаевых для официантов

Telegram-бот, который считает чаевые. Не бюджет и не баланс: только чай за смену
и честный итог «чистыми за смену» (чай минус траты смены).

## Принципы

- **Только чаевые, без остатка.** Мы регистрируем чай и траты за смену, а не ведём
  бюджет. Никакого «сколько у тебя всего денег».
- **Главная цифра — «За сегодня»** = чай − траты смены.
- **Два счёта:** наличные и карта — чтобы видеть долю чая наличкой.
- **Запись сразу, отмена одной кнопкой.** Никаких многошаговых диалогов.
- **Без ИИ.** Разбор сообщений — детерминированные правила, покрытые тестами.
- **Сутки начинаются в 6 утра.** Смена принадлежит дню, в который началась:
  чай, записанный в час ночи, идёт во вчерашнюю смену, а не в новый день.
- **В базе нет имён.** Только числовой Telegram id, суммы и даты — см.
  [Приватность](#приватность).

## Как пользоваться

| Пишешь | Что происходит |
|---|---|
| `чай 500` | +500 чаевые, наличные |
| `смена 2500` | +2500 подработка, наличные |
| `кофе 200, такси 350` | несколько трат сразу |
| пересланное сообщение банка о чаевых | сумма (с чеком и %) запишется сама на карту |
| `работаю 22 24 26` | поставить смены на эти дни; вечером бот спросит про чай |
| 🧾 Закрыть смену | внести траты за смену кнопками → «чистыми за смену» |

Кнопки: **📋 История**, **🧾 Закрыть смену**, **📊 Статистика** (мини-ап).
Команды: `/undo` — отменить последнюю запись, `/reset` — очистить журнал,
`/help` — подсказка, `план 2500` — цель по чаю на смену.
Приватность: `/privacy` — что хранится, `/export` — забрать своё файлом,
`/delete` — стереть себя без следа.

## Мини-ап и статистика

Кнопка «📊 Статистика» открывает Telegram Mini App (`webapp/index.html`,
раздаётся ботом по `/app`): за сегодня/неделю/месяц/всего чистыми, план смены,
календарь-теплокарта месяца, история с правкой записей, внесение трат смены.
Кнопка «Итоги месяца» открывает тёмный плакат-«чек» (звание месяца, рекорд
смены) — его скриншотят и показывают коллегам.
Данные считаются из журнала (`stats.py`), авторизация — подпись initData.
Из банковских уведомлений сохраняются чек и процент чаевых.

В 22:30 МСК бот сам предлагает закрыть смену тем, у кого сегодня был доход.

## Приватность

Бот задуман для компании коллег, и разумный вопрос «а автор видит, сколько я
зарабатываю?» решается тем, что смотреть не на что.

**Что лежит в базе:** числовой Telegram id, записи (сумма, категория,
нал/карта, время, исходный текст), даты смен, план смены, токен Google
Календаря, если подключён.

**Чего в базе нет:** имени, `@username`, телефона, номера карты. Имя бот берёт
из самого сообщения Telegram, когда здоровается, и не сохраняет — поэтому
таблицу нельзя прочитать как ведомость с фамилиями.

**Никто не видит чужого.** Ни рейтинга, ни сравнения с коллегами, ни админки с
суммами: в коде нет ни одного запроса, который отдаёт одному человеку данные
другого. Единственные два запроса без фильтра по пользователю —
`get_onboarded_user_ids` и `get_user_ids_with_shift_on` в `db.py` — тянут
только идентификаторы для вечернего напоминания, без сумм.

**Что может человек:** `/privacy` — посмотреть этот список внутри бота,
`/export` — забрать все свои записи CSV-файлом, `/delete` — стереть себя
целиком и безвозвратно.

Честная граница: бот разбирает сообщения вида «чай 500», поэтому читает их
открытым текстом — сквозное шифрование с такой механикой несовместимо, и
обещать его было бы враньём. Кому этого мало — код открыт, поднимается свой
экземпляр со своим токеном и своей базой за десять минут (см. Установку).

## Установка

1. Создай бота у [@BotFather](https://t.me/BotFather), возьми токен.
2. В [Supabase](https://supabase.com) создай проект, в SQL Editor выполни `schema.sql`.
   **Обновляешься со старой версии?** Вместо этого выполни миграции по
   порядку, начиная с той, на которой остановился: `migration_v2.sql` …
   `migration_v6.sql`. Все, кроме последней, только добавляют — `v6`
   намеренно удаляет из `users` колонки `username`, `first_name` и
   неиспользованные `yandex_*`.
3. `cp env.example .env`, заполни `BOT_TOKEN`, `SUPABASE_URL`, `SUPABASE_KEY`.
4. Локально: `pip install -r requirements.txt && python main.py` — запустится polling.
5. Деплой на Render: подключи репозиторий (найдёт `render.yaml`), задай те же
   переменные плюс `WEBHOOK_HOST=https://твой-сервис.onrender.com` — включится webhook.

## Тесты

Офлайн, без Supabase/Telegram (внешние зависимости замоканы):

```bash
python tests/test_parser.py    # разбор ввода и банковских уведомлений
python tests/test_stats.py     # расчёт статистики (нал/карта, календарь)
python tests/test_workday.py   # операционные сутки, ночная смена
python tests/test_api.py       # подпись initData + приём трат /api/shift_spend
# всё сразу: python -m pytest tests/ -q   (pytest ставится отдельно)
```

## Структура

```
main.py          # точка входа: polling локально / webhook на Render
handlers.py      # все хендлеры и клавиатуры
parser.py        # разбор сообщений (правила, без ИИ)
workday.py       # операционные сутки: смена принадлежит дню, в который началась
stats.py         # расчёт статистики для мини-апа (чистые функции)
db.py            # Supabase, журнал entries
webapp_api.py    # API мини-апа, подпись initData, OAuth-callback Google
jobs.py          # вечернее напоминание закрыть смену, self-ping Render
schema.sql       # схема БД, migration_v*.sql — миграции по порядку
webapp/          # мини-ап (одна страница, без сборки)
tests/           # офлайн-тесты
legacy/          # старая версия (не используется)
```
